## 本轮目标

完成无需真实供应商凭证即可实现和验证的 Live v1 基础版本：

- 后端能生成与当前教学模式一致的 Qwen 实时配置，使用语义轮次判断并等待配置确认；
- 前端具备 GPT Live 式聚焦通话界面、静音、停止回答、流式双方字幕和清楚的保存状态；
- WebRTC 连接、Provider 事件、重连和结束流程按 connection epoch 隔离，旧回调不能改变新会话；
- live-v1 会话创建幂等，转写保存可去重，结束前等待在途保存；
- 保留现有 mock 演练与完整学习报告，不把 mock 显示为真实模型；
- 现有数据与 API 合同保持可读，账号导出和删除仍覆盖新增数据。

真实 Qwen 的 G1–G7 实验、真机延迟和打断指标必须有凭证后另行验收，本轮不得用模拟结果替代。

## 硬检查

以下检查全部退出码为 0：

```powershell
uv run --project apps/api pytest apps/api/tests
uv run --project apps/api ruff check apps/api/app apps/api/tests apps/api/alembic
pnpm lint:web
pnpm typecheck:web
pnpm build:web
```

新增自动检查覆盖：

- live-v1 创建重试幂等及冲突；
- 语速、纠错模式、辅助语言、耐心档位进入实时配置；
- SDP 信令成功与媒体 active 状态分开；
- connection epoch 拒绝过期写入；
- Provider 条目标识去重且同 ID 不同内容冲突；
- ending 阶段仅接受已登记条目的收尾，finalize 对账后才 completed；
- 不完整用户转写不进入会话总结证据；
- 刷新后恢复原会话合同，且不会自动重新打开麦克风；
- 超过心跳阈值的活动会话进入可恢复的 ending 状态。

## 软验收

每项至少 8/10，且不能有阻断项：

| 维度 | 通过标准 |
|---|---|
| 通话清晰度 | 不阅读说明也能开始、静音、停止回答、打开文字输入和结束 |
| 状态真实性 | 收音、生成、播放、重连和保存状态互不冒充 |
| 学习体验 | 慢速与三种纠错模式的含义清楚，学习者停顿有耐心 |
| 可靠性 | 快速取消、断线、重连期间结束、晚到事件不会串会话或重新开麦 |
| 可维护性 | 页面、传输、状态、字幕和音频职责分开，无新的全局状态依赖 |
| 数据可信度 | 草稿、终稿、被打断回答和保存失败均有明确语义 |
