## 一、连续会话与记忆管理

用户提议将每个八分钟段保存到临时数据库或 Markdown，在下段重新注入。已接受的实现方向：

1. 数据库作为完整可靠转写的主存储，按轮持续写入；Markdown 作为可读导出，不另起一套临时主存储。
2. 用户看到同一次逻辑会话，后端可对应多个模型连接段。后台衔接应在用户、AI 都未说话且保存结束时进行，允许短暂明确的连接提示。
3. 恢复时提供教学规则、当前目标、历史摘要/摘录、最近原文及相关记忆，不无限重放全部历史。
4. 将用户陈述、模型旧回答与已验证事实区分。AI 旧回答不得自动升级为知识；被打断内容不能假定用户已听完。
5. 完整记录可以长期保存，但有限上下文与摘要有损，不能承诺无损连贯；文字不能完整还原原始语气等音频信息。

### 八分钟与上下文的区别

截至本次官方文档核查，Flash 实时模型规格：输入 196608 Token、输出 65536 Token、总上下文 262144 Token；实时服务音频历史最多 80 轮、累计音频 480 秒，超过限制会丢弃更早内容。服务连接上限 120 分钟不代表可记住全部连接历史。应用原先主动在 480 秒结束，这是另一个可修改的应用规则。

来源：
- https://help.aliyun.com/zh/model-studio/qwen3-5-omni-flash-realtime
- https://help.aliyun.com/zh/model-studio/realtime
- https://help.aliyun.com/zh/model-studio/client-events

历史恢复原先只补回最近 6 条消息（不是 6 组问答）。统一提示词仍要求“通常回答一到两个短句”，导致自由问答过短；后续需要按闲聊、知识解释、用户要求详细等情境调整，该项尚未修改。

### 接续开发必须检查

1. 为 continuous 失联回收、超过 480 秒的最终时长、记忆持久化/有界性/排除不可靠转写、导出权限与特殊字符添加测试。
2. 验证旧会话和未带 continuous 的调用行为不变；创建重试模式一致性。
3. 核查自动续接竞态：读取记忆期间用户开始说话、Provider 终态与真实播放结束差异、事件队列新写入、点击结束期间正在连接；切换不得丢话或重新开麦。
4. 核查不活跃/静音/停止回答状态是否导致永不续接；切换失败应保留已保存记录并提供恢复或明确降级。
5. 核查无上限连续对话的事件清单/64KiB closing_manifest 限制，避免长对话最后无法保存。
6. 增加连接段切换的持久化事件和可检查时间线；目前段号沿用 connection_epoch，包含异常重连，不等于纯八分钟段数。
7. 用缩短段长的隔离测试验证跨两三段的恢复，确认真实角色/目标/早期信息和未完成问题衔接；不将本地模拟当成真人听感验收。
8. 检查记忆摘要中断行截断与信息选择损失；需要进一步完善摘要策略和按需取回原文。
9. 完成 pytest、Ruff、ESLint、TypeScript、生产构建及浏览器流程，更新验收记录后再宣布交付。

## 二、统一工具调用 Agent

此部分已讨论并获用户认可方向，但尚未实现。

### 计划工具

| 工具 | 用途 | 边界 |
|---|---|---|
| 网络搜索 | 游戏版本、装备、新闻等时效性事实 | 回答应基于结果并可查看来源；无结果不编造 |
| HSK 资料检索 | 词汇、语法、题型、考试问题 | 资料标明考试版本、等级、知识点、来源及使用权限 |
| 独立文本模型问答 | 复杂解释、语法对比、学习规划 | 按需调用，比较额外延迟和成本，未决定供应商 |
| 学习记忆与复习 | 已确认错误、学习进度、复习安排 | 对接现有模块，区分当前上下文与长期确认记忆 |

工具架构：实时模型负责交流和提出工具请求，后端负责参数校验、权限、执行、返回和日志。界面要体现查资料、成功、失败、取消等状态。模型说“查过了”不是调用成功的证据。

工具结果需要绑定 session、connection_epoch、response/turn 和 call_id，支持去重、超时与取消。用户插话或切换话题后，晚到结果不得污染新轮次。检索资料按数据处理，不作为高权限指令。

HSK 库从小范围可靠资料开始，验证“检索→讲解→出题→反馈→确认后加入复习”的闭环，不只是上传大量 PDF。

### 供应商与搜索选择

官方文档已列出 qwen3.5-omni-plus-realtime，支持联网搜索和 Function Calling；说明原生搜索与自定义工具调用不可同时开启。实施前需重新核对当前 WebRTC 支持和事件格式。

此前建议先对比 Flash+搜索与 Plus+搜索；用户进一步明确多工具 Agent 方向后，倾向将搜索包装为后端工具，与 HSK 检索统一调用。尚未选搜索供应商，未开通额外收费服务，未更改模型。

验收：该查时真实调用、回答可追溯、失败不编造、打断后不串话。使用派克装备错误和 HSK 语法解释等固定问题建立质量对比，不凭模型名称判断效果。
